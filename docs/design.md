# Решение

Цель — проверяемый проезд А → Б в симуляции с тремя работающими сенсорами.
Ubuntu 22.04, ROS 2 Humble, Ignition Fortress, Python. Один пакет ab_robot.
Docker изолирует Linux от macOS, Xvfb и noVNC дают графический интерфейс.

Собственная дифференциальная модель Xacro, статическая карта из геометрии мира,
AMCL по лидару, Nav2 (NavFn + DWB). Карта не заменяет сенсоры: лидар и облако
точек depth-камеры обновляют costmap. GPS NavSat из Fortress через ros_gz_bridge
задаёт фактическую географическую привязку старта; Python преобразует WGS84
waypoints в map и вызывает NavigateToPose с ограниченным временем ожидания.

TF: AMCL публикует map → odom, DiffDrive публикует odom → base_link,
robot_state_publisher публикует геометрию сенсоров и колёс. Один издатель на ребро.
GPS не публикует TF. /clock поступает только от симулятора.

Проверки: модульные тесты координат и автомата маршрута, чистый colcon build,
живые сенсоры и TF, потребители препятствий, измерение финальной ошибки,
контактный сенсор на корпусе и колёсах, два независимых проезда,
недостижимая цель и тайм-ауты. Видео только с реально запущенных Gazebo и RViz.

Сдача остаётся локальной. Возможные ограничения подтверждаем результатами,
не считаем наличие файлов доказательством автономного проезда.
